# Live demo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Swap the shared Supabase project's data for `seed.sql` plus a demo starting state for every Done/In Review story, with a safe restore, and give Jie Ching a PDF demo script with one card per story.

**Architecture:** Two scripts in `backend/scripts/`. `demo_db.py` backs up, wipes, swaps and restores the data through `supabase db query --linked` (no Docker here). `demo_data.py` builds each story's starting state through the running backend's API, signed in as the seeded accounts, reusing `verify_live.py`'s `Context`, `db_query` and `expect*` helpers. The demo script is HTML outside the repo, printed to PDF with the Playwright Chromium already installed.

**Tech Stack:** Python 3 + httpx + pytest (backend venv `/home/jclim/projects/ConnectSphere/backend/.venv`), Supabase CLI 2.121.0 at `/home/linuxbrew/.linuxbrew/bin`, Playwright Chromium (`frontend/`).

**Spec:** `docs/superpowers/specs/2026-11-04-live-demo-design.md`

## Global Constraints

- Demo record names start `Demo · <ID> · ` (middle dot U+00B7, spaces either side). Never `live-check`, never a seed name.
- Demo dates on or after `2026-12-01` SGT, except stories flagged `time_relative`, whose dates are computed from load time.
- Seeded accounts and password: `verify_live.ACCOUNTS`, `verify_live.W7_STAFF_ACCOUNTS`, `SEEDED_PASSWORD = "Cs1234"`; coordinator 2 is `coordinator2@connectsphere.dev`.
- Story pool: Product backlog sheet rows with Status `DONE 🥳` or `IN REVIEW 🥹` (73 on 2026-11-04).
- Backups go under `~/connectsphere-backups/<YYYY-MM-DD-HHMM>-<label>/`, never in the repo. Layout: `<schema>.<table>.json` (JSON array of rows) per table plus `_counts.json` (`{"schema.table": n}`). The 2026-11-04-1637 backup already uses it.
- The demo script and its PDF live in `~/connectsphere-demo/`, never in the repo.
- No product code, schema or migration changes. Defects found go in `docs/DEFECTS.md` and on the PDF's "flagged" page.
- Commit only `backend/scripts/demo_*.py`, `backend/tests/test_demo_*.py`, `docs/superpowers/**` and any `docs/DEFECTS.md` entry.

## Review Focus

1. **Restore changes rows**: inserting a backup row fires triggers (history, notifications, `on_auth_user_created` profiles), so the restored data differs from the backup even when counts match. Test: restore SQL sets triggers off for the whole load; rehearsal spot-checks 3 rows byte-for-byte (Task 2).
2. **Wipe misses a reference table**: deleting `notification_types` (or another migration-filled table) breaks notifications app-wide and `seed.sql` won't put it back. Test: wipe SQL never names a table in `REFERENCE_TABLES`; rehearsal compares reference counts (Tasks 1, 2).
3. **A stale backup**: teammates write between 2026-11-04 and the swap. Swap refuses a backup older than 1 hour (Task 1), so Task 6 takes a fresh one.
4. **Loader run twice / story picked twice**: `--load` twice must not duplicate; `--reset <ID>` must touch only that story's rows. Test in Task 3.
5. **Single quotes in names/values in generated SQL** (e.g. a backed-up comment "can't"): restore must not build SQL by string concatenation of row values. Test: a row containing `'` and `$$` restores intact (Task 1).

### Task 1: `demo_db.py` — backup, wipe, restore SQL, counts

**Files:**
- Create: `backend/scripts/demo_db.py`
- Test: `backend/tests/test_demo_db.py`

**Interfaces:**
- Consumes: `verify_live.db_query(sql: str) -> list[dict]`, `verify_live._supabase_query(*args) -> CompletedProcess` (for running a SQL file: `db query --linked -f <file>`).
- Produces:
  - `REFERENCE_TABLES: frozenset[str]` — `public` tables whose rows come from migrations (at least `public.notification_types`; derive the rest by grepping `insert into` in `supabase/migrations/` and excluding what `seed.sql` inserts).
  - `backup(label: str, root: Path = BACKUP_ROOT) -> Path` — writes the layout in Global Constraints for every `public` base table plus `auth.users`, `auth.identities`; returns the directory.
  - `wipe_sql() -> str` — one SQL text: deletes all rows of every `public` base table not in `REFERENCE_TABLES`, then all `auth.users` rows.
  - `restore_sql(backup_dir: Path) -> str` — `wipe_sql()` then the backup's rows inserted with triggers off (`set local session_replication_role = replica` unless the rehearsal proves the CLI role can't; then the builder's fallback, recorded in the docstring), rows passed as JSON literals through `json_populate_recordset(null::<table>, $tag$…$tag$)` with a tag that can't occur in the data.
  - `compare_counts(expected: dict[str, int], actual: dict[str, int]) -> list[str]` — human-readable mismatch lines, empty when equal.
  - `table_counts() -> dict[str, int]`.
  - CLI: `python scripts/demo_db.py backup <label>` · `swap <backup-dir>` (refuses unless `<backup-dir>/_counts.json` exists and is < 1 hour old; runs `wipe_sql()`, then `supabase/seed.sql`, then prints counts; does not run the loader) · `restore <backup-dir>` · `rehearse <backup-dir>` (runs `begin; <restore_sql>; <counts query>; rollback;` and prints `compare_counts`).

### Task 3: `demo_data.py` — the story registry, naming, load and reset

**Files:**
- Create: `backend/scripts/demo_data.py`
- Test: `backend/tests/test_demo_data.py`

**Interfaces:**
- Consumes: `verify_live.Context`, `Session`, `expect`, `expect_status`, `db_query`, `ACCOUNTS`, `W7_STAFF_ACCOUNTS`.
- Produces:
  - `DEMO_PREFIX = "Demo · "`; `demo_name(story_id: str, label: str) -> str` → `"Demo · CR-99 · Held booking"`.
  - `@dataclass Story: id: str; title: str; build: Callable[[Context], dict]; time_relative: bool = False` — `build` returns `{"label": id-or-url, …}` of what it created, for the PDF.
  - `STORIES: dict[str, Story]` and decorator `@story(id, title, time_relative=False)`.
  - `demo_start(days: int, hour: int, duration_h: int, *, relative: bool = False) -> tuple[str, str]` — ISO SGT start/end; `relative=False` counts from `2026-12-01`, `True` from now.
  - `delete_story(story_id: str) -> int` — deletes rows named `Demo · <id> · %` (events with bookings first, then blocks by `notes`, equipment, venues; same order and reasons as `verify_live.delete_throwaway_bookings`); returns events deleted.
  - `load(ctx, ids: list[str] | None = None) -> dict[str, dict]` — for each story: skip if any `Demo · <id> · %` event/venue/equipment already exists, else `build`; writes the results to `~/connectsphere-demo/loaded.json`.
  - `reset(ctx, ids: list[str] | None = None)` = `delete_story` then `load` for those ids.
  - CLI: `python scripts/demo_data.py --load [ID …] | --reset [ID …] [--api URL]`; stops at the first failed story with `"<ID>: <reason>"`.
